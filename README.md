# テーブル表示制御プラグイン

Kintoneのテーブル全体を、ログインユーザーの所属組織・グループに応じて表示／非表示にします。テーブルのフィールドコードを選択し、許可と拒否をそれぞれ設定できます。

**A案の画面表示制御です。データのアクセス権を変更するものではありません。** CSV出力、REST API、検索結果、一覧、グラフ、外部連携からの閲覧は制限しません。

## 導入

1. `dist/table-visibility.zip` をKintoneシステム管理の「プラグイン」で読み込みます。ZIPは展開しません。
2. 対象アプリの設定から「プラグイン」を開き、「テーブル表示制御」を追加します。
3. プラグイン設定を開き、「対象テーブル」で名前とフィールドコードを確認して選択します。
4. 許可／拒否する組織・グループにチェックします。名称・コードで検索でき、複数選択できます。
5. 必要な組織に「下位組織も含める」を設定します。初期状態では直接所属のみです。
6. 「その他の利用者」を設定します。初期値は「非表示」です。
7. 必要に応じてルールを追加し、「保存」を押します。
8. アプリ設定へ戻り、**「アプリを更新」**して反映します。

同じテーブルに複数ルールは作れません。ルールをすべて削除して保存・アプリ更新すると、このプラグインによる表示制御を解除できます。ルールを設定していないテーブルには何もしません。

## 判定例

| 対象テーブル | 許可組織 | 許可グループ | 拒否グループ | その他の利用者 |
|---|---|---|---|---|
| 見積明細 | 営業部（下位組織を含む） | 管理職 | 外部委託 | 非表示 |

- 営業部・その下位組織、または管理職グループのユーザーに表示します。
- 外部委託グループにも所属している場合は非表示です。
- どの条件にも一致しないユーザーは非表示です。

優先順は **拒否一致 → 許可一致 → その他の利用者**。組織とグループの条件はORです。両リストが空でも既定値に従います。「その他の利用者：表示」なら、拒否リストだけを設定する使い方もできます。管理者の自動的な特別扱いはありません。

## 対応画面・動作

| 画面 | PC | モバイル |
|---|---|---|
| レコード詳細 | 対応 | 対応 |
| レコード追加・複製 | 対応 | 対応 |
| レコード編集 | 対応 | 対応 |
| レコード印刷 | 対応 | 対象外 |
| 一覧・一覧内編集・検索結果・グラフ | 対象外 | 対象外 |

- 画面の表示イベントで、対象テーブルを先に非表示にし、所属確認後に許可対象のみ表示します。
- 拒否／許可の所属情報は毎回取得し、ブラウザの永続キャッシュには保存しません。所属変更は次回の画面表示に反映されます。開いたままの画面は再読み込みしてください。
- 下位組織を含むルールがある場合は組織一覧も取得し、親組織をたどって判定します。組織・グループ一覧は100件ずつ全件取得します。
- APIリクエストは15秒でタイムアウトします。取得失敗時は対象を非表示のままとし、画面に案内を表示します。
- 保存済み設定が破損している場合は、画面内のすべてのテーブルを非表示にして管理者への確認を案内します。
- ゲストユーザーはUser APIの制約により対象外です。判定に失敗した場合は非表示になります。通常ユーザーがゲストスペース内アプリを使う場合のAPI URLは考慮していますが、実機確認が必要です。
- 最大100テーブル、設定JSONは60,000バイトまで。Kintone標準の上限内に収めるための本プラグイン独自制限です。

## 運用時の確認事項

- **必須フィールド**：非表示にしてもKintoneの必須条件は変わりません。非表示の必須項目に値がない場合、追加・編集で保存できないことがあります。設定画面に必須項目を表示します。事前に既定値や入力担当者の運用を確認してください。プラグインが値を消したり、必須条件を外したりすることはありません。
- **フィールドコード・組織コード・グループコードの変更／削除**：変更後はプラグイン設定を開き直して再選択してください。設定画面は削除済み項目を残して警告し、そのままの保存を拒否します。閲覧時に対象テーブルが見つからない場合は警告します。
- **他のカスタマイズ**：同じテーブルを表示／非表示にするプラグインやJavaScriptと併用すると、実行順によって結果が変わります。対象テーブルを重複して制御しないでください。
- **表示前の一瞬の見え方**：Kintoneの描画と表示イベントの順序に依存するため、一瞬の表示まで完全に防ぐ保証はありません。機密保護の境界には利用しないでください。
- 不正な設定JSONの場合は、プラグインをアプリから削除・再追加して再設定できます。この操作で当該プラグイン設定は失われるため、正常時の設定を控えてください。レコード値の変更は行いません。

## 開発・再ビルド

Node.js 22以降を使用します。

GitHubから取得した直後でも `npm ci`、`npm test`、`npm run verify` は実行できます。検証済みZIPもリポジトリに含めています。同じプラグインIDで再ビルドするには、別途保管した署名用秘密鍵を `.keys/plugin.ppk` に復元してから `npm run build` を実行してください。秘密鍵はGitHubには保存していません。

```sh
npm ci
npm test
npm run build
npm run verify
```

設定画面だけを確認する場合は `npm run preview` を実行し、`http://127.0.0.1:4178` を開きます。架空のデータを使う開発用プレビューで、保存先はそのタブのセッションストレージです。Kintoneには接続しません。

現行の公式 `@kintone/cli` の `plugin keygen` / `plugin pack` を使用します。初回ビルド時に `.keys/plugin.ppk` を生成し、以後のビルドで再利用します。**この鍵を紛失すると同じプラグインIDで更新できません。秘密鍵は配布ZIPとは分けてバックアップしてください。** `.keys` はGit対象外で、ZIPに含めません。既存成果物がある状態で鍵がない場合、ビルドは中断します。

成果物は `dist/table-visibility.zip`、IDは `dist/plugin-id.txt`、チェックサムは `dist/SHA256SUMS` です。実行時の外部ライブラリ・CDN依存はありません。ネットワーク呼び出しは同じテナントの公式APIだけで、APIトークン・パスワードは保存しません。

## 検証範囲

自動テストでは許可／拒否、兼務、下位組織、空条件、不正設定、API失敗／タイムアウト、100件超の候補、PC／モバイルのイベント、画面遷移競合、設定UIの操作・保存・復元をモック環境で検証します。パッケージ検証では署名、ID、マニフェスト、ソース一致、秘密鍵非混入を確認します。

実テナントの接続情報は未提供のため、Kintone上の読み込み・動作は未検証です。導入後は次を確認してください。

- 許可のみ・拒否のみ・両方・どちらも該当しないユーザーで、設定どおりになること。
- 直接所属と下位組織、複数組織、利用しているグループ（静的／動的）で期待どおりになること。
- PCとモバイルの詳細・追加・複製・編集、およびPCの印刷画面。
- 非表示のまま保存しても既存テーブル値が保持され、必須項目の運用に問題がないこと。
- 通信失敗時は非表示で案内が出ること。他プラグインとの競合がないこと。

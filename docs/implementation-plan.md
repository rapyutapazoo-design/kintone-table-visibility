# 実装計画・判断記録

## 目的・決定事項
ユーザー承認済みのA案を実装する。テーブル全体の画面表示を、組織・グループの許可／拒否条件で制御する。データのアクセス権は変更しない。

- 同じテーブルに1ルール、複数テーブル対応。
- 拒否一致 > 許可一致 > 既定値（初期値は非表示）。各リスト内および組織とグループはOR。
- 組織ごとに下位組織を含むか選択。階層は閲覧時に取得し組織変更に追従。
- PC詳細・追加・編集・印刷、モバイル詳細・追加・編集に対応。
- 認証はログインセッション。資格情報の保存なし。所属取得失敗時は非表示。
- 一覧、CSV、REST API、検索、外部連携の表示／取得制限は対象外。
- ゲストユーザーはUser APIの制約により対象外。通常ユーザーのゲストスペース内利用ではKintone APIのみゲストURLに変換。

## ファイル・実装手順
1. src/core.js: 設定検証・所属／階層の判定を副作用のない処理として実装。
2. src/api.js: User APIの100件ページング、15秒タイムアウト、設定候補と所属取得。
3. src/config.*: 日本語設定画面。検索・複数選択・欠損設定の検出・保存。
4. src/runtime.js: 同期的な初期非表示、非同期判定、画面遷移競合防止。レコード値は不変。
5. src/manifest.json / scripts/: 現行の公式cli-kintoneで署名付きZIP生成。秘密鍵は.keysに保管し配布物から除外。
6. tests/: 判定、API、画面イベント、設定UI、パッケージ整合性。
7. README.md: 導入・設定例・制限・実機検証項目。

## 検証とリスク
複数所属、拒否優先、空条件、既定値、深い階層、取得失敗、不正設定、ページング、画面遷移を自動テストする。設定UIはモックAPIによるDOM操作で保存と復元を検証する。署名・マニフェスト・ZIP内容を検証する。

実テナントは接続情報がないため、自動検証はモック環境。非表示の必須項目はKintoneの保存条件を緩和しない。設定画面とREADMEで事前確認を案内する。読み込み直前の一瞬の表示や他のカスタマイズによる再表示は、画面表示制御では防御境界にできない。

## 自律実行フェーズ
調査: 公式API確認、新規空フォルダ確認。検討: A案承認済みのため比較のやり直しは省略。計画: 本書。実装: コアと設定UIを分担。レビュー: 自動検証と独立レビュー。プッシュ: 未依頼かつGit未初期化のため省略。

モデル設定: stage one。ローカル調査・計画・統合は親モデル継続（phase切替 not_applied）。独立した設定UIはスキル既定のstandard候補 gpt-5.6-sol / medium を指定。実効モデルはツールによる確認がないため unverified。モデル変更のためだけの委譲は行わない。

レビューは設定判定の誤りを重視し、スキルのhigh候補 gpt-6-astra / high を指定した独立担当に委譲（実効モデルは unverified）。指摘されたフィールドコードとObject継承プロパティの衝突をSetで修正し、設定UIの回帰テストを追加。
